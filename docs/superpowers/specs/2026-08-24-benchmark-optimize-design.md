# Benchmark & Optimize — Design Spec

**Date:** 2026-08-24
**Milestone:** 3 (see `DESIGN.md`)
**Status:** Approved decisions from design Q&A; ready for implementation planning.

## 1. Purpose & scope

Milestone 3 makes the book fast, with proof: measure msgs/sec and memory on the
Milestone 1 baseline, swap in optimized data structures behind the frozen
public API, and record before/after numbers for every optimization
individually. The Milestone 1 spec promised the API "must not change when the
internals are swapped" — this milestone cashes that promise.

**In scope**
- `book_bench`: a book-only benchmark executable with deterministic synthetic
  workloads (links `xeas_core` only — no feed, no I/O)
- Full-day macrobenchmark methodology via the existing `itch_replay` CLI
  (manual, no data files in repo), plus one additive change: a peak-RSS line
- Optimized `Book` internals: banded flat tick-indexed price array with
  occupancy bitmaps and an overflow map; intrusive per-level FIFO lists over a
  pooled, index-addressed order slab; a flat open-addressing order index
- `BaselineBook`: a frozen verbatim copy of the Milestone 1/2 internals,
  compiled only into bench and test binaries, as the A/B and differential oracle
- `TapeGen`: a seeded generator of valid-by-construction event tapes, plus the
  invariant-fuzzing and differential suites deferred from the Milestone 1 spec §7
- `BENCH.md`: the recorded numbers and the methodology to reproduce them

**Out of scope** (later milestones or never)
- Matching, networking, multi-threading, SIMD (or never, per `DESIGN.md`)
- Live feeds / MoldUDP64 (Milestone 4)
- Feed-side optimization (decoder, reader, mmap) — unless the book-vs-feed
  split measurement in §2 shows the feed dominates; the Milestone 2 spec §6
  no-mmap rationale stands until numbers contradict it
- Gzip input (unchanged from Milestone 2)
- Any change to the public surface of `book.h` — signatures, query complexity
  contracts, `BookError` conditions, the post-throw unspecified-state rule

**Scale expectations (informative):** a busy day is ~300–450M messages with a
few million concurrent live orders; the Milestone 1 baseline runs at roughly
1–4 GiB peak RSS. That footprint, and the per-event cost of
`std::map`/`std::list`/`std::unordered_map` node churn, are this milestone's
targets. The order-index lookup runs on *every* book event (Add checks for
duplicates; everything else resolves the order), so it is on the hot path even
though `DESIGN.md` names only the three level-side structures — this spec adds
it as a fourth, separately measured optimization.

## 2. Benchmark harness & methodology

### Microbenchmark: `book_bench`

```
book_bench [--workload steady|insert|deep|all] [--events N=10000000]
           [--warmup N=1000000] [--seed S=1] [--repeat R=5] [--impl new|baseline|both]
```

A hand-rolled harness: generate a tape with `TapeGen` (§6), apply it in a
timed `std::chrono::steady_clock` batch loop, repeat `R` times, report the
**median and min** of Mmsg/s (min is the least-noise estimator on a quiet
machine). Output per (workload, impl): events, elapsed, Mmsg/s, ns/event, the
new/baseline ratio when `--impl both` (the default), and peak RSS via
`getrusage(RUSAGE_SELF).ru_maxrss` (bytes on macOS, KiB on Linux — normalized
in code). The seed and event counts are printed on every line, so any recorded
number is reproducible from its own output.

**Rationale (no Google Benchmark):** the metric of record per `DESIGN.md` is
batch throughput over millions of events, which a steady_clock loop measures
exactly as well as Google Benchmark's auto-iteration machinery — that machinery
earns its keep for sub-microsecond single ops, not multi-second batches. The
same-binary baseline-vs-new comparison needs custom driving anyway, and the
project's only dependency is gtest, deliberately. Per-op latency percentiles
are also rejected: a per-event clock read costs about as much as the op it
would measure and distorts the result.

Workloads (all deterministic from `--seed`, generated by `TapeGen`):

| Workload | Shape | Stresses |
|---|---|---|
| `steady` | warm the book to ~100k live orders, then N events with an ITCH-like mix (Add 400‰ / Delete 250‰ / Execute 150‰ / Cancel 100‰ / Replace 100‰), prices random-walking around a mid | the real replay hot path — flagship number |
| `insert` | adds spread across many levels, then delete them all | level create/destroy, price-structure insert |
| `deep` | wide price range with occasional far-out prices | band growth, bitmap next-best scans, the overflow path |

### Macrobenchmark: full-day replay

The existing `itch_replay` CLI on a real uncompressed day — the same manual
workflow as Milestone 2's golden replay; no data files are checked in. The only
code change is additive: a peak-RSS line in `src/itch_replay_main.cpp` (the
`getrusage` wrapper lives in the main file; platform code stays out of the
libraries). Run the same file before and after each optimization phase, same
machine, Release build.

**Book-vs-feed split:** compare `book_bench steady` Mmsg/s against end-to-end
`itch_replay` msgs/sec. If they are close, the book dominates and feed-side
optimization stays out of scope; if the feed dominates, that is a finding for
a future milestone, not license to widen this one.

### Where the numbers live: `BENCH.md`

A new file at the repo root: a machine/compiler/flags header, the micro table
(phase × workload × impl → Mmsg/s, speedup, peak RSS), and the macro table
(file, msgs/sec, MiB/s, peak RSS, live-orders peak). Reproducibility rules
documented at the top: `-DCMAKE_BUILD_TYPE=Release` (must be stated — the
project's default build type is empty), fixed seeds, median of 5 repeats,
single-threaded, CPU frequency scaling noted. `README.md` gets one summary line
plus a link when the milestone lands.

**Rationale:** the README is an overview and the spec is a design-time
artifact; results accrue after both. A dedicated file keeps the numbers next to
their methodology.

## 3. Optimized internals

The public section of `book.h` is byte-identical. Everything below is the
private section and `src/book.cpp`. `apply()` keeps its exact shape: same
validation order, same `BookError` conditions, all validation before any
mutation, post-throw state unspecified — no rollback machinery.

### 3.1 Price structure: banded flat array + two-level bitmap + overflow map

Per side, per book:

- A lazily allocated **band** of `u32` slots covering `[lo, lo + slots.size())`
  ticks, each slot holding a level-pool index + 1 (`0` = empty). The band is
  created 4,096 ticks wide, centered on the first in-band `Add`, and grows
  geometrically (×2, re-anchored to cover the new price with padding) up to
  `kMaxBand = 262,144` ticks. Growth is a rare O(band) copy of `u32`s. The
  constants are named in `book.cpp` and explicitly provisional — they are
  finalized from a measured price-range histogram of a real day during phase 3,
  as named-constant tuning, not CLI knobs.
- A **two-level occupancy bitmap**: one bit per tick (64 ticks per word) plus
  one summary bit per word. Finding the next-best level after a level empties
  is a `<bit>` `countr_zero`/`countl_zero` scan — effectively O(1) even across
  long empty gaps. A cached `best` slot per side is maintained on insert/erase.
- An **overflow `std::map`** (same comparators as today) for prices outside the
  band's maximum window around the anchor. Correctness is unconditional; only
  speed differs by path. An overflow order *can* be the best (a lone $0.01
  bid), so `best_bid()`/`best_ask()` return the better of the cached in-band
  best and `overflow.begin()` — still O(1).
- A private `for_each_level(side, fn)` helper merges band and overflow in
  strict best-first order. It is the single ordered walker, used by
  `check_invariants`, `BookTestPeer`, and any query needing order — so the
  sorted-levels invariant stays a real check (§4), not one the structure makes
  trivially true.

**Rationale (rejected alternatives):**
- *Flat array over the full u32 price domain* — 4Gi slots per side times up to
  65,536 books. Impossible.
- *Paged/chunked directory (hash of fixed-size pages)* — adapts to price drift
  automatically, but adds a page-directory lookup to the Add path, burns a page
  (~2–16 KB) for every junk far quote (real days carry $0.01 and $199,999
  orders), and roughly doubles the implementation and verification surface. An
  exact overflow map handles the outliers with none of that.
- *Fixed 64Ki-tick band per side* — 256 KB of slots per side across thousands
  of active books is gigabytes of slot arrays alone, defeating the RSS goal.
  The band must start small and grow only when the symbol actually trades wide.

### 3.2 Order pool + intrusive per-level FIFO lists

Orders move out of per-level `std::list` nodes (~48–64 B each with allocator
overhead, one heap allocation per order) into a per-book slab pool: a growing
`std::vector<OrderNode>` with an intrusive freelist, addressed by **u32
indices, not pointers** — indices survive vector growth, so no stable-address
chunking is needed. Each level is an intrusive doubly-linked FIFO threaded
through the pool (`head`/`tail` + per-node `prev`/`next`), preserving strict
time priority. Levels come from an identical per-book level pool, so band
slots and order handles are u32 throughout.

### 3.3 Order index

Phases 2–3 keep `std::unordered_map<OrderId, OrderHandle>` (the handle shrinks
to 8 bytes). Phase 4 replaces it with a flat **open-addressing map**:
power-of-2 capacity, linear probing, maximum load ~0.7, and a Fibonacci-mixed
key (`id * 0x9E3779B97F4A7C15` — ITCH order references are near-sequential, so
identity hashing would cluster catastrophically). Deletion uses
**backward-shift** (no tombstones); an empty slot is marked by
`handle.node == kNone`, so no `OrderId` value is reserved. At ~5M live orders
this is ~16 B/slot at ~8M slots ≈ 130 MB, versus 400+ MB of `unordered_map`
nodes — and one cache line per lookup on the structure every event touches.

### 3.4 Declarations

The private section of `Book` (replacing the current one; public section
untouched):

```cpp
private:
    static constexpr std::uint32_t kNone = 0xFFFF'FFFF;

    struct OrderNode {                 // pool slab entry, addressed by u32 index
        OrderId id;
        Qty remaining;
        std::uint32_t prev, next;      // intrusive FIFO links; kNone at the ends
    };                                 // 24 bytes

    struct Level {                     // level pool entry
        std::uint32_t head = kNone;    // front = oldest (highest time priority)
        std::uint32_t tail = kNone;
        std::int64_t total_shares = 0; // cached aggregate, maintained incrementally
        Price price;                   // a level knows where it lives, so the
        Side side;                     // handle no longer carries side/price
    };

    class OrderPool {                  // freelist over a growing vector slab
    public:
        std::uint32_t allocate(OrderId id, Qty qty);
        void release(std::uint32_t idx);
        OrderNode& operator[](std::uint32_t idx);
        const OrderNode& operator[](std::uint32_t idx) const;
    private:
        std::vector<OrderNode> nodes_;
        std::uint32_t free_head_ = kNone;
    };
    // LevelPool: identical pattern over Level.

    template <class Compare>           // std::greater<> bids, std::less<> asks
    struct FlatSide {
        Price lo = 0;                             // band = [lo, lo + slots.size())
        std::vector<std::uint32_t> slots;         // level index + 1; 0 = empty
        std::vector<std::uint64_t> words;         // occupancy, 64 ticks per word
        std::vector<std::uint64_t> summary;       // one bit per word
        std::uint32_t best = kNone;               // cached best in-band level
        std::map<Price, std::uint32_t, Compare> overflow;  // far prices, exact
        std::size_t level_count = 0;              // band + overflow
    };

    struct OrderHandle {               // 8 bytes (was Side+Price+ptr+iterator)
        std::uint32_t node;
        std::uint32_t level;
    };

    class OrderIndex {                 // phase 4: open addressing, linear probe,
    public:                            // Fibonacci-mixed key, backward-shift erase
        OrderHandle* find(OrderId id);
        const OrderHandle* find(OrderId id) const;
        void insert(OrderId id, OrderHandle h);   // precondition: id absent
        void erase(OrderId id);
        std::size_t size() const noexcept;
    private:
        struct Slot { OrderId id; OrderHandle h; };  // empty <=> h.node == kNone
        std::vector<Slot> slots_;      // power-of-2 capacity; max load ~0.7
        std::size_t size_ = 0;
    };
```

`insert_order`/`erase_order` are rewritten against these structures with the
same responsibilities. `find_order` becomes: index lookup → node (remaining) +
level (side, price). Internals stay nested private structs in `book.h`.

**Rationale (no `include/xeas/detail/` headers):** nothing outside `Book`
needs these types; files on the public include path imply API; and the
friend-based `BookTestPeer` pattern depends on the nesting.

## 4. Invariants & the test backdoor

`check_invariants` keeps invariants 1–5 from the Milestone 1 spec §6 verbatim,
iterating via `for_each_level` so level sortedness is verified against the
merged band+overflow order — the `book.cpp` comment "kept so Milestone 3
internals stay honest" is now load-bearing, and the failing direction of
invariant 4 becomes reachable for the first time. Three structure-specific
invariants are added:

6. Bitmaps agree with slots: a tick bit is set iff its slot is non-empty; the
   summary agrees with the words; the cached `best` agrees with a fresh scan.
7. The overflow map contains only out-of-band prices; no price is present in
   both the band and the overflow.
8. Intrusive links are well-formed: `head`/`tail` consistent, `prev`/`next`
   reciprocal, chain node count matches the index; no node is simultaneously on
   the freelist and in a level.

`BookTestPeer` is rewritten against the new internals with the same test
intents. Corruption helpers map naturally (`corrupt_total_shares`,
`zero_order_qty` via index→node, `drop_from_index`); `corrupt_handle_price`
becomes `corrupt_handle_level` (point a handle at the wrong level), since the
handle no longer stores a price. **All 108 existing tests must pass with at
most mechanical `BookTestPeer` edits; zero changes to any test that uses only
the public API.**

## 5. Baseline preservation: `BaselineBook`

A verbatim frozen copy of the Milestone 1/2 internals — `class BaselineBook`
plus overloads `apply(BaselineBook&, const Event&)`,
`check_invariants(const BaselineBook&)`, `is_crossed`, and the same queries —
in `bench/baseline_book.{h,cpp}`, built as a static library `xeas_baseline`
linked *only* by `book_bench` and `book_fuzz_test`. Never linked into
`xeas_core`, `xeas_feed`, or `itch_replay`. The file is headed "FROZEN copy of
Milestone 1/2 internals — reference oracle, do not improve," and it is kept
permanently: any future internal change gets the same differential oracle for
free. Cost: ~260 duplicated, frozen lines.

**Rationale (rejected alternatives):**
- *Compile-time switch / template parameter* — the frozen `book.h` cannot grow
  a template knob; comparison would require two builds; and same-binary
  differential fuzzing — the strongest correctness tool this milestone has —
  would be impossible.
- *Git-tag the baseline, measure across commits* — numbers rot as compilers
  and flags drift, the comparison is never same-binary-fair, and again no
  in-process differential fuzzing.

## 6. Fuzz / differential testing

This is the invariant fuzzing the Milestone 1 spec §7 deferred ("invariant
fuzzing with random valid tapes").

**`TapeGen`** (`bench/tape_gen.h`, header-only, shared by the bench and the
fuzz tests): a seeded `std::mt19937_64` generator that maintains its own shadow
set of live orders (flat vector with swap-remove for O(1) random victim
selection), so every emitted event is **valid by construction** — Cancels never
over-cancel, Deletes/Replaces target live ids, ids are unique. Prices
random-walk around a mid with a configurable per-mille event mix, occasional
band-edge prices (exercising growth) and rare far-out prices (`far_price_ppm`,
exercising overflow and overflow-is-best). Falls back to Add when no orders are
live. Crossing is allowed — the book stores crossed as given — so checks are
crossed-tolerant, exactly like the replay driver's classification.

```cpp
struct TapeGenOptions {
    std::uint64_t seed = 1;
    Price mid = 1'000'000;             // $100.00
    int far_price_ppm = 100;           // out-of-band outliers, parts per million
    // per-mille event mix (sums to 1000):
    int add = 400, del = 250, execute = 150, cancel = 100, replace = 100;
};

class TapeGen {
public:
    explicit TapeGen(TapeGenOptions opts);
    Event next();
    const std::vector<OrderId>& live_order_ids() const;  // for final sweeps
};
```

**Differential protocol:** apply each event to both a `Book` and a
`BaselineBook`. Every K events, compare `best_bid`/`best_ask`/`order_count`/
`level_count`, `size_at` on recently touched prices, and `find_order` on
sampled live ids; require `check_invariants` on the new book to return empty
or crossed-only findings. At the end, compare `find_order` for *every* live id
and `size_at` for every touched price.

## 7. Implementation phasing

Each optimization lands as its own phase, and each phase ends the same way:
all tests green, fuzz differential green, a `BENCH.md` row. This is what makes
"with before/after numbers" per-optimization rather than one blob:

1. **Harness first** — `book_bench`, `BaselineBook`, `TapeGen`, and the fuzz
   suites, with `Book` still on baseline internals (the differential runs
   baseline-vs-baseline, validating the harness). Record the baseline micro
   numbers and one real-day macro run.
2. **Order pool + intrusive lists** (keep `std::map` levels and
   `std::unordered_map` index). Measure.
3. **Banded flat array + bitmaps + overflow.** Measure; finalize band
   constants from the real-day price-range histogram.
4. **Open-addressing `OrderIndex`.** Measure; final real-day macro run with
   peak RSS.

## 8. What not to do

- Do not touch the public surface of `book.h`: identical signatures, queries
  stay `const`, allocation-free, O(1) or O(log levels); `BookError` conditions
  and validation order unchanged; post-throw state remains unspecified — no
  rollback machinery.
- Do not put invariant checks, asserts, or stats inside `apply()` —
  `check_invariants` stays strictly out-of-band.
- Do not add dependencies (no Google Benchmark), threads, SIMD, or mmap
  without a measurement showing the reader is the bottleneck.
- Do not optimize the feed this milestone unless the §2 split measurement says
  the feed dominates.
- Do not link `BaselineBook` into production targets, and do not "improve" it.
- Do not let ITCH knowledge leak into the core: band constants are
  book-internal tuning, and the layering grep stays clean — `src/book.cpp`,
  `include/xeas/book.h`, and `bench/` include no itch/router/replay headers.
- Do not land an optimization without its `BENCH.md` before/after row and a
  green fuzz differential.

## 9. Project skeleton & testing

```
include/xeas/book.h          — public surface byte-identical; private section replaced
src/book.cpp                 — rewritten internals; apply() shape/validation unchanged
src/itch_replay_main.cpp     — additive: peak-RSS line
bench/baseline_book.h/.cpp   — frozen BaselineBook (library xeas_baseline)
bench/tape_gen.h             — TapeGen (header-only, shared by bench and fuzz tests)
bench/book_bench_main.cpp    — bench CLI (executable book_bench)
tests/book_fuzz_test.cpp     — Pool / BandGrowth / InvariantsV2 / FuzzDifferential / BenchSmoke
BENCH.md                     — recorded numbers + reproduction methodology
```

CMake: `add_library(xeas_baseline bench/baseline_book.cpp)` (needs only the
`include/` dir, links nothing); `add_executable(book_bench
bench/book_bench_main.cpp)` linking `xeas_core xeas_baseline` — **not**
`xeas_feed`, cashing the Milestone 2 CMake promise that "benchmarks can link
book-only"; test binary `book_fuzz_test` linking those plus gtest, with
`bench/` on its include path, via `gtest_discover_tests`; same `-Wall -Wextra`
pattern throughout.

**Test strategy** (TDD, ~28 new tests → ~136 total; timing itself is never
asserted — bench logic is tested, numbers are recorded manually):

1. **`Pool`** (~6) — allocate/release/reuse; index stability across slab
   growth; freelist integrity surfaced by the checker; release-then-reallocate
   reuses slots.
2. **`BandGrowth`** (~7) — first add anchors the band; out-of-band add within
   the max window grows the band and preserves every query; far price lands in
   overflow; a lone overflow order is the BBO; band and overflow levels
   interleave in correct sorted order; next-best scan across word and summary
   boundaries; growth while the book is crossed.
3. **`InvariantsV2`** (~6) — one corruption per new invariant via the
   rewritten `BookTestPeer`: bitmap/slot disagreement, stale cached best,
   in-band price wrongly in overflow, broken prev/next reciprocity, node on
   freelist and in a level, wrong-level handle.
4. **`FuzzDifferential`** (~7) — seeded `TapeGen` runs against `BaselineBook`:
   default mix at 100k events; replace-heavy, far-price-heavy, high-churn
   (book repeatedly drains to empty), and crossed-heavy mixes; a multi-seed
   loop (10 seeds × 20k events) as one test; and baseline-vs-baseline
   agreement, validating the harness itself.
5. **`BenchSmoke`** (~2) — each `book_bench` workload runs 10k events untimed
   and the resulting book passes `check_invariants`.

The 108 existing tests are the regression floor: they run unmodified (public
API) or with mechanical `BookTestPeer` edits (§4), green after every phase.
